# DSH 插件回归测试

## 选择最小可验证目标

1. 先写出缺陷触发条件、期望行为及需要观察的状态。
2. 阅读目标实现与现有 `demo-test/` 测试，不以测试替身的行为替代真实实现。
3. 新测试一律放工作区根 `demo-test/`，不在业务目录加入测试数据。

## 分层验证

- 纯路径与元信息函数直接调用真实实现，覆盖正常、边界及非法输入。
- 文件操作使用 `mkdtemp()` 创建本次隔离目录，测试结束 `t.after()`
  清理；不得触碰真实 DSH home、凭据、技能或工作区文件。
- Cordis 服务使用真实 `Context`，只替换外部服务或网络；
  参考 `other-plugins.test.mjs` 的服务启动和卸载流程。
- 网络替身校验请求 URL、固定 revision、方法、body、AbortSignal 和大小上限。
- 客户端可先编译真实 TSX，以可控 Hook 或真实 React 测试；
  编译产物留在内存，不污染业务目录。

## 必测的异步行为

1. 两个并发写入按调用顺序完成，前一个失败不堵塞后一个。
2. 读取、搜索或格式化的旧响应不覆盖最新输入。
3. 卸载取消待处理请求并移除监听、计时器及句柄。
4. 提交前取消不留下半成品；替换失败能恢复旧数据或明确保留备份。
5. 外部数据被修改、超限或返回非法结构时，错误码和本地状态一致。

用可控 Promise 驱动竞态，不使用长时间 sleep 或依赖公网时序。
ZIP 等二进制测试数据可在内存生成，不要求仓库长期保留原始下载包。

## 执行与报告

从仓库根运行需要的测试，例如：

```sh
node --test demo-test/skill-store.test.mjs demo-test/other-plugins.test.mjs
```

- 修改后运行相关旧回归，不能只检查新增用例。
- 独立执行语法、类型和构建检查；测试通过不代表类型或发布文件正确。
- 浏览器测试页使用本地随机端口，不启动真实用户 profile；
  结束显式停止本次后台进程与端口。
- 报告实际用例数、失败或跳过项、平台和模拟接口范围。
  没有运行的检查必须明确说明。
